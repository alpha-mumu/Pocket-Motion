Pocket Motion 4  ·  Osmo Pocket 4 实况照片导出工具（Windows 免安装 · 单文件版）
版本 v4.2.1（v4.2.0 的文档合规重打包 · 功能完全一致）

============================================================
零、这一版变了什么
============================================================
【v4.2.0】把上一版目录里的 ffmpeg.exe、app.ico、使用说明.txt、
一键自检.bat、备用启动.bat、上游源码补丁\ 全部封装进主程序：
· 交付包里只有一个 Pocket Motion.exe，双击即用，不需要任何其它文件。
· 不再有外置 ffmpeg.exe：视频引擎压缩内置，首次启动自动释放到
  %LOCALAPPDATA%\PocketMotion4\bin\ 并缓存（有哈希校验，只释放一次）。
  之后启动直接复用，也不会在运行目录里生成任何文件。
· 两个批处理的功能搬进了界面（左侧最下方「帮助与内置资源」卡片）：
    「运行一键自检」   = 原 一键自检.bat，结果直接显示在日志区
    「使用说明」       = 原 使用说明.txt，弹窗阅读
    「导出说明与补丁」 = 需要文件时，把说明与上游 Dart 补丁写出到指定目录
· 若环境变量冲突导致窗口起不来，可直接命令行加 --browser 或
  --no-browser，效果等同原 备用启动.bat（见第四节）。
· 识别规则、导出引擎、元数据写入、动态视频校验等全部功能保持不变，
  v4.1.1 的动态照片兼容性修正一并保留。

运行环境：Windows 10/11，需要系统自带的「Microsoft Edge WebView2
Runtime」（随 Edge 安装，绝大多数机器已有）。若确实缺失，程序会弹提示
并自动回退到默认浏览器，功能仍可用。

============================================================
一、快速开始
============================================================
1. 把 Pocket Motion.exe 单独放到任意目录（中文、空格路径均可）。
   注意：务必先把 exe 从压缩包里解压出来，不要在压缩软件窗口里双击。
2. 双击 → 弹出程序自己的窗口，不启动浏览器。
   首次启动约 5~15 秒：单文件自解压 + 内置视频引擎首次释放，属正常现象；
   之后启动会明显变快。程序只监听 127.0.0.1，不联网、不上传任何文件。
3. 用完点窗口右下角「退出程序」（或直接关窗口）即可完全退出。
   正在扫描/导出时关窗口会弹确认，避免误中断任务。

============================================================
二、为什么「看起来像静态图片」？怎么确认它其实是动的？
============================================================
这是实况/动态照片本身的构成决定的，不是导出失败：

· Apple 实况照片 = 一张静态 HEIC 封面 + 一个 3 秒 MOV 视频。
  Windows 看图软件打开 .HEIC 只会显示静态封面。**必须把同名的
  .HEIC 与 .MOV 两个文件一起导入 iPhone 相册**（AirDrop 两个一起选、
  或用 iCloud 照片同步；不要分开用微信/QQ 传，会被改名拆散）。
  导入后在照片上长按才会动。
· Google 动态照片 = 一个 .jpg，静态图在前、3 秒 MP4 附在文件尾部。
  Windows 看图软件同样只显示前面的静态图。**导入 Google 相册**后
  才有动态播放效果；部分国产 Android 相册也支持。
· 确认视频确实在文件里：
    1) 导出日志会打印「动态视频校验通过：3.00s / 90 帧 / hevc」；
    2) 点「验证导出结果 · 检查是否含动态视频」，逐个解码并列出帧数；
    3) 点「运行一键自检」，末尾 RESULT: PASS 表示整条链路正常。
  日志若出现「校验异常 / 解码失败 / 只有 1 帧」，把日志发回即可定位。

============================================================
三、操作步骤
============================================================
· 素材源目录：选 SD 卡的 DCIM\DJI_001，或直接选 DCIM（勾「递归扫描」）。
· 点「扫描 / 刷新」，Osmo Pocket 4 的 3 秒 MP4 会出现在「实况」标签页。
· 勾选素材 → 选「Apple 实况照片」或「Google 动态照片」→「导出选中素材」。
· 输出在「导出位置\live\」：
    Apple  ：<文件名>I.HEIC + <文件名>I.MOV（必须一起导入 iPhone 相册）
    Google ：<文件名>A.jpg（单文件，导入 Google 相册）
· Google 模式下若相册仍不播放，勾选「动态照片视频转 H.264」重新导出。
· 「视频」「照片」标签页可把原片无损复制到 movie\ / photo\。
· 识别有误时：选中文件后用「设为实况 / 设为视频」手动纠正，
  或点「诊断选中文件」查看判定依据。

============================================================
四、帮助与内置资源 / 隐藏参数
============================================================
界面左侧「帮助与内置资源」卡片：
  · 使用说明        弹窗阅读本文件
  · 运行一键自检    生成 7 类模拟素材，跑完整识别→导出→解码校验
  · 导出说明与补丁  在导出位置写出「PocketMotion4-说明与源码补丁\」
                    （含使用说明.txt 与上游 Flutter 的 Dart 源码改动）

命令行参数（排障用）：
  Pocket Motion.exe               默认：弹出自带窗口
  Pocket Motion.exe --browser     强制改用默认浏览器打开界面
  Pocket Motion.exe --no-browser  只启动本地服务，手动访问 http://127.0.0.1:8787/
  Pocket Motion.exe --selftest    跑内置自检，结果写入 %TEMP%\PocketMotion4_selftest_result.txt
  Pocket Motion.exe --port=8899   指定本地服务端口（8787 被占用时用）
（若旧版残留的 PYTHONHOME / PYTHONPATH 等环境变量干扰启动，
  在该目录打开命令行，先 set PYTHONHOME= 与 set PYTHONPATH=，再执行 exe。）

============================================================
六、主要改动（功能， v4.1.1 起保持不变）
============================================================
1. 实况识别改为多信号判定（任一命中即为实况）：
     · MP4 容器精确时长（默认 0.30~5.00 秒，界面可调）—— Pocket 4 主判据
     · DJI TPLG / LIVEPHOTO / MOTIONPHOTO 标记（兼容 Pocket 3 / 4P）
     · 与同目录静态 JPG 成对
     · 文件名含 LIVE / LP / MOTION 标记
   支持 moov 位于文件尾部、递归扫描子目录、排除 LRF 代理文件。
2. 拍摄设备型号改为自动解析：依次从配套 JPG 的 EXIF、
   MP4 QuickTime mdta、固件签名解析真实型号；界面可手动指定覆盖。
   拍摄时间依次取 文件名时间戳 → JPG EXIF DateTimeOriginal →
   MP4 creation_time → 文件修改时间。
3. 封面帧按实际时长取中点（3 秒 → 1.5 秒），与 MOV 的 still-image-time
   轨道、Google XMP 的 PresentationTimestampUs 严格对齐。
4. Apple 实况：源为 HEVC 时零重编码提取关键帧做 HEIC 封面；写入完整
   Apple MakerNote、ContentIdentifier、LivePhotoAuto / VitalityScore、
   mebx 定时元数据轨与 tref→cdsc，支持 iPhone 自动播放与重选封面。
5. Google 动态照片：优先用相机配套原始 JPG（无损），注入 EXIF 与两代
   GCamera XMP（MotionPhoto* 与 MicroVideo*）；内嵌视频无损重封装
   （剔除 DJI 私有 dbgi 轨、moov 靠前，可选 H.264 兼容转码）后拼接。
6. 提供「设为实况 / 设为视频」「诊断选中文件」「验证导出结果」。

============================================================
七、验证情况（重要）
============================================================
· 打包后 exe 的内置自检通过（RESULT: PASS）。自检覆盖 7 类样本：
  无标记的 3 秒 HEVC（Pocket 4 主场景）、带 TPLG_VIDEO_LIVEPHOTO 的
  4P 素材、固件签名变体、moov 在文件尾部、H.264 源、10 秒长视频、
  配套 JPG 与 QuickTime 设备元数据。
· 强校验不只看字节标记，而是真正解码数帧：MOV 完整解码且帧数 > 1；
  Google JPG 按相册方式从文件尾截出视频段解码确认 3.00s / 90 帧；
  校验两代 XMP 字段与长度一致性；faststart 源直接注入仍可解码 90 帧。
· 单文件版额外验证：解压目录里只有一个 exe；干净环境变量下自检、
  独立窗口创建与页面 DOM 加载、退出程序、--no-browser 排障模式；
  内置 ffmpeg 首次释放与二次复用；英文路径与中文含空格路径。
· 说明：验证用的是按 DJI 文件规范构造的模拟素材，尚未用 Osmo Pocket 4
  真机原片跑过。若真机文件识别不符合预期：
    1) 可临时用「设为实况」手动纠正，或调整界面的时长区间；
    2) 点「诊断选中文件」复制信息发回，即可针对真实固件格式精确适配。

============================================================
八、故障排查
============================================================
· 看起来是静态图片 → 先读第二节；点「验证导出结果」看帧数。
  只要日志显示 3.00s / 90 帧，文件就是动态照片，去手机相册里看。
· 导入 iPhone 后仍不动 → 确认同名 .HEIC + .MOV 一起导入、文件名未改、
  未通过微信/QQ 分开传；用 AirDrop 或 iCloud 照片同步最稳。
· Google 相册里不动 → 勾选「动态照片视频转 H.264」重新导出，并确认
  导入的是 Google 相册（不是系统自带相册）。
· 双击后没有窗口 / 弹「未能启动独立窗口」
    → 安装或修复「Microsoft Edge WebView2 Runtime」；期间程序会自动
      回退到默认浏览器，功能不受影响。也可用 --browser 强制浏览器模式。
· 弹「内置 ffmpeg 数据格式损坏 / 校验失败」
    → exe 下载不完整或被安全软件改写，重新下载完整文件再试。
· 首次启动慢 / 被杀毒软件拦截 → 把 exe 加入白名单；内置视频引擎被
  瞬时拦截时导出会自动重试 3 次，也可先点「运行一键自检」预热。
· 界面没自动出现但程序在运行 → 手动访问 http://127.0.0.1:8787/
  （8787 被占用时会自动改用随机端口，以界面日志里的地址为准）。
